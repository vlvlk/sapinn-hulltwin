# PINN-HullTwin — архитектура MVP «Живой корпус»

## 1. Обнаруженные публичные данные (результат поиска)

### Основной кандидат: Shifts / Marine Cargo Vessel Power Consumption Dataset
- Источник: Zenodo record 7057666 (DOI 10.5281/zenodo.7057666), лицензия CC BY-NC-SA 4.0
- Объём: ~87 MB zip (реальные данные грузового судна), бенчмарк Shifts Project (arXiv 2206.15407)
- Целевая переменная: мощность / потребление энергии судна; содержит признаки, описывающие погодные условия
  и состояние моря (ветер, волны) — то есть готовая «судовая» выборка с распределительным сдвигом
  (три части: train / val / test со сдвигом — идеально для проверки экстраполяции PINN)
- Почему подходит: единственный крупный реально скачиваемый датасет реального судна
  с power + weather; часть test намеренно «сдвинута» (похоже на деградацию/смену условий) —
  это прямой тест на восстановление эффекта обрастания.
- Ограничение: нет торсионметра/оборотов/топливомера — функционал MVP упрощается до баланса
  «скорость–погода–мощность», k_s(x) идентифицируется как интегральный коэффициент по периодам.

### Вспомогательные / справочные
| Источник | Что даёт | Доступность |
|---|---|---|
| Kaggle «Ship Performance Insights/Predictions», «Ship Fuel Consumption & CO2» | Схема логов, бейзлайны ML | Публично, но данные синтетические — только для пайплайна/смоук-тестов |
| Li, Du et al. 2022 (Comm. Transport. Res., Части I–III) + GitHub yuquandu/Data-driven-Ship-Fuel-Efficiency-Modeling | Код fusion voyage report + AIS + ECMWF/Copernicus; 130 обученных моделей контейнеровозов 8100–14000 TEU | Код и модели открыты, реальные логи — нет (в репо фейковые сэмплы) |
| arXiv 2510.03003 (transfer learning noon→HFD) | Пример признаков: STW, RPM, draft, wave/swell height & direction, wind direction | Данные закрытые |
| arXiv 2202.01000 (Data Processing Framework for Ship Performance) | Лучшие практики препроцессинга HFD: квази-стационарность, выбросы лага | — |
| Fishing ships sensor data (Zenodo 3563390) | 3 судна, 1 месяц, сырые сенсоры | Публично, но рыболовные суда — малоприменимо |
| Copernicus Marine + ECMWF ERA5 | Метоокеан по треку (волны, ветер, течения) — обязательный вход Ур.1 | Публично, бесплатно |

Вывод: реальных судовых логов с оборотами/моментом/топливом в открытом доступе нет.
Стратегия MVP — двухконтурная валидация:
1) синтетика (симулятор «корпус–винт–море» с injected k_s-профиль и деградацией винта) — проверка идентифицируемости;
2) Shifts power-consumption — проверка на реальных данных (упрощённая версия функционала).

## 2. Скоуп MVP

Внутри MVP:
- Генератор синтетических рейсов (физическая модель сопротивления + шум/дрейф датчиков)
- PINN-наблюдатель: нейронный ODE Кармана + k_s(x) + винтовая развязка + баланс мощности
- Метрики: восстановление k_s(x) vs ground truth синтетики; error прогноза мощности на Shifts
- Отчёт/ноутбук-дашборд: поле k_s(x) по длине корпуса, траектория деградации, confidence band

Вне MVP (следующие этапы): MPC-оптимизатор, планировщик очистки, онлайн-стриминг, transfer learning флота.

## 3. Архитектура (уровни и модули)

```
data/
  synthetic/   # генератор: Карман + ITTC-1957 + Bowden-Davison ΔCf(k_s) + K_T/K_Q винта + волны
  external/    # Shifts power_consumption, Copernicus/ERA5 fetcher
  logs/        # приёмник реальных noon/HFD логов (схема Smart Maritime SVD)

src/hulltwin/
  physics/     # karman.py, friction.py (ITTC+roughness), propeller.py (K_T,K_Q), waves.py (R_aw)
  pinn/        # ks_net, theta_net, kp_net; loss() как в концепте; ODE-solver (torchdiffeq)
  observer/    # обучение, планирование эксперимента (скоростные прогоны), оценки неопределённости
  energy/      # R_T(V), η_D, топливная карта
  viz/         # поле k_s(x), сравнение с «очистками», отчёт

tests/         # unit: физика vs аналитика; e2e: идентифицируемость k_s на синтетике
notebooks/     # 01_synthetic_id.ipynb, 02_shifts_power.ipynb
```

Стек: Python 3.14 (поддерживается PyTorch >= 2.9; torch.compile совместим с 3.14 с релиза 2.10),
менеджер пакетов — uv (быстрое разрешение окружений, lockfile), ruff + mypy.

Два варианта DL-ядра (выбор на шаге 4):
- Вариант A (по умолчанию): PyTorch 2.10+ + torchdiffeq + torch.compile — зрелая экосистема,
  простой дебаг, лучшая совместимость с ноутбуками/дашбордами.
- Вариант B (максимальная производительность): JAX + Equinox + Diffrax — jit-компиляция
  нейронного ODE целиком, заметно быстрее на маленьких сетях/частых решателях ОДУ,
  но жёстче с функциональным стилем и отладкой.

Инфраструктура данных: numpy/pandas/xarray, pydantic-схемы, matplotlib/plotly.

## 5. Ключевые риски MVP

- Shifts-датасет без RPM/момента → винтовая развязка не проверяется на реальных данных (только на синтетике)
- Дневное разрешение реальных данных → k_s(x) восстанавливается грубо; в синтетике — проверка тонкой структуры
- Разделение «волны vs обрастание» критично зависит от качества метеоданных → fusing по методике Li et al.
